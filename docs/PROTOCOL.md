# 数据通道协议规范

本规范定义主机与 Phosphor 固件之间的数据通道，适用于 v1.6 基线的全部修订。
通道承载在 USB CDC-ACM 虚拟串口上，链路参数（波特率、数据位、流控）不参与传输
控制。实现主机驱动、扩展固件命令或分析数据语义时以本页为准；固件侧实现见
[USB_STACK.md](USB_STACK.md)。

## 1. 链路参数

| 项目 | 值 |
|---|---|
| 物理层 | USB 全速 12Mbps，OTG1 控制器 |
| 设备类 | CDC-ACM（通信接口 + 数据接口） |
| VID:PID | `2E3C:5740` |
| 端点 | EP0 控制 64B；EP1 批量 IN/OUT 64B；EP2 中断 IN 64B |
| 主机侧名称 | Windows `USB 串行设备 (COMx)`；Linux `/dev/ttyACM*` |
| 描述符字符串 | 厂商 `Phosphor`，产品 `Phosphor DSO-153` |
| 名义波特率 | 921600（仅描述符与线路编码中的值，不影响传输） |

主机可以用任意波特率打开端口。CDC 线路编码（`SET_LINE_CODING`）固件照收但不用。

## 2. 传输模型

- 命令由主机写入 EP1 OUT，单字节；连续写入的多个命令按字节流依次解析；
- 命令在 CDC OUT 中断上下文处理，响应为亚毫秒级，不经过主循环；
- 数据由设备从 EP1 IN 主动上传，一帧 = 一次完整组帧与发送；
- 协议无 ACK：命令是否生效只能从随后的数据帧推断，未知命令被静默忽略；
- 带参数的命令由状态机接收，参数可与命令字节分处不同 OUT 包；参数接收期间
  不接受新命令。

## 3. 命令表

| 值 | 名称 | 参数 | 行为 |
|---|---|---|---|
| `0x00` | STOP | 无 | 停止连续发送与画面流；在途帧不中断 |
| `0x01` | SINGLE | 无 | 按当前数据源上传一帧 |
| `0x02` | STREAM | 无 | 按当前数据源连续发送，直到 `0x00` |
| `0x03` | SCREEN | 无 | 上传一帧 301 点屏幕波形（与数据源无关，兼容旧主机） |
| `0x04` | DIAG | 无 | 上传 20 字节栈诊断（§3.2） |
| `0x05` | FAULT | 无 | 上传 56 字节 HardFault 现场（§3.3） |
| `0x06` | KEY | 1 字节键码 | 注入按键队列（§3.4） |
| `0x07` | SETTINGS | 无 | 上传 `0x2000A528` 起 64 字节（UI 状态区快照，兼容保留） |
| `0x08` | RAMREAD | 4 字节地址 + 1 字节长度 | 读内存（§3.5） |
| `0x0D` | SETPARAM | 角色 + 目标 | 直设档位（§3.6） |
| `0x0E` | WRITERAM | 地址 4 + 长度 1 + 数据 | 写调试窗口 SRAM（§3.6） |
| `0x0F` | APPLY | 1 字节角色 | 按当前字段值重跑一遍刷新链路 |
| `0x10` | SRC | 1 字节源 | 选择数据源（§3.7） |

参数一律小端。`0x08` 的长度字段为 0 表示 256。

`0x09`–`0x0C` 曾属于已删除的整屏截屏链路，现已回收：旧固件可能仍响应，新固件
静默；主机调用时应把无响应当作"能力不存在"而不是故障。扩展新命令从 `0x11`
起（见第 10 节）。

发送/武装期间下发 `0x01` 或 `0x03` 只会在发送空闲时插入一帧，帧在途时该请求被
丢弃。画面流进行中只受理 `0x00`（防整帧卡死，见 §3.8）。

## 4. 帧格式

```
偏移   长度  字段      说明
0      2     同步字    0xA5 0x5A
2      2     长度 N    负载字节数，小端
4      2     序号      逐帧递增，65535 后回绕
6      1     标志      见第 5 节
7      1     保留      恒 0x00
8      N     负载
8+N    1     校验      帧 8 字节头 + 负载逐字节和的低 8 位
```

各命令的负载与标志：

| 命令（源） | 负载 | N | 标志 |
|---|---|---|---|
| `0x01`/`0x02`，源 0 | 4096 点原始采样 | 4096 | `0x03` |
| `0x01`/`0x02`，源 1 | 301 点屏幕波形 | 301 | `0x04` |
| `0x01`/`0x02`，源 2 | 画面块 | 8 + w·h·2，≤4096 | `0x20` |
| `0x03` | 301 点屏幕波形 | 301 | `0x04` |
| `0x04` | 栈诊断 | 20 | `0x00` |
| `0x05` | 故障现场 | 56 | `0x00` |
| `0x07` | UI 状态窗口 | 64 | `0x0A` |
| `0x08` | 内存片段 | 1..512 | `0x00` |
| `0x0D` | 无 | 0 | — |

帧总长上限 4105 字节。

## 5. 标志位

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | LIVE | 数据取自实时环形缓冲，不是冻结快照 |
| 1 | CHK_ADV | 校验值为发送起始时刻计算，仅作参照 |
| 2 | SCREEN | 负载是屏幕波形 |
| 3 | SETTINGS | 负载是状态窗口快照 |
| 4 | — | 保留（曾用于已删除的截屏链路） |
| 5 | IMG | 负载是画面块（§3.8） |
| 6–7 | — | 保留 |

LIVE 与 CHK_ADV 可同时置位。不存在 ACK 类信息，不得用标志位判断命令接受与否。

## 6. 校验语义

`checksum = (sum(frame[0 : 8+N])) & 0xFF`

原始采样帧的负载来自 ADC 环形缓冲，发送期间 DMA 仍在写入，起始时刻算出的校验与
实际发出的字节可能不一致——这类帧置位 CHK_ADV，主机**不得**因校验不符丢帧。
屏幕波形帧来自独立缓冲，发送短于一个刷新周期，校验通常成立；诊断/故障/快照帧
校验恒成立。

主机约定：CHK_ADV 置位时，校验只用来发现帧头/长度错位；未置位时校验失败应丢帧
并重新同步。

## 7. 时序

| 项目 | 数值 |
|---|---|
| 命令响应延迟 | 亚毫秒（OUT 中断内解析） |
| 主循环周期 | 约 200ms（只有键码注入受它约束） |
| 4096 点单帧 | 约 65ms（65 个 64 字节包） |
| 帧间隔（连续模式） | 由 IN 完成中断续帧，不受主循环约束 |

序号连续；跳号说明丢帧（主机读不及时或端点忙）。

## 8. 数据语义

### 8.1 原始采样（4096 点）

源 `0x2000025D`，ADC1 经 DMA1_CH0 环形写入的 16384 点缓冲中的连续片段，8 位无
符号码值。发送期间缓冲继续被覆盖，因此：帧间不保证时间连续、不保证触发点对齐、
校验可能不符（CHK_ADV）。触发位置协议不上报。

### 8.2 屏幕波形（301 点）

源 `0x2000425E`，与屏幕显示点列一一对应，随显示刷新更新，适合与屏幕比对或低速
观察；为抽取后数据，精度低于原始帧。

### 8.3 栈诊断负载（`0x04`，20 字节）

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | 魔数 `STK1` | |
| 4 | `stack_min` | 观测到的最低栈地址 |
| 8 | `stack_peak` | 峰值字节数 |
| 10 | `painted` | 1 表示水印已铺设，数据可信 |
| 11 | `usb_err` | 端点忙提交失败计数（低 8 位） |
| 12 | `stack_base` | 栈底（取自 Flash 字面量） |
| 16 | `stack_top` | 初始 SP |

### 8.4 故障现场负载（`0x05`，56 字节）

14 个 32 位字：CFSR / HFSR / MMFAR / BFAR（偏移 0–12，来源 `0xE000ED28..0xE000ED38`）、
异常栈帧 R0–R3/R12/LR/PC/xPSR（偏移 16–44）、故障计数（48，本上电周期）、魔数
`FLT1`（52）。记录区在 `0x2000BF00`，跨软件复位保留；另有 6 字摘要存
`0x2000BF60`（魔数 `0x464C5432`/`FLT2`，含 CFSR/HFSR/BFAR/PC/LR）跨冷启动保留。
同一上电周期前 3 次故障自动软复位，第 4 次起处理器停住。

### 8.5 键码（`0x06`）

| 键码 | 含义 | 键码 | 含义 |
|---|---|---|---|
| 1 | 关机（立即断电） | 8 | 确定 |
| 2 | RUN/停止 | 9 | 拨轮左 |
| 3 | 上 | 10 | 未标定（无可辨识现象） |
| 4 | 下 | 11 | 详细信息 |
| 5 | MODE | 12 | 触发边沿 |
| 6 | AUTO | 13 | 长按 AUTO（自动校正，改写校准值） |
| 7 | 拨轮右 | 14 | 返回 |

`0xFF` 表示无按键，作为参数会被忽略。设备队列容量 20 项，但补丁的注入槽位只有
1 字节，主循环（约 200ms）每轮取走一个——**相邻键码间隔必须 ≥240ms**，更密会
被覆盖。键码 13 会改设备校准值，下发前需按说明书处理探头。

### 8.6 档位直设（`0x0D`）与辅助命令

设置结构基址 `0x2000001C`，已标定字段：

| 地址 | 字段 | 取值 |
|---|---|---|
| `+0x01` | 垂直档位 | 0..8（10mV..5V） |
| `+0x03` | 探头倍率 | 0/1 = ×1/×10 |
| `+0x0D` | 时基索引 | 0..23（500nS..20S） |
| `+0x0E` | 底栏选中项 | 1..7（**从 1 起**） |

注意：`+0x59` 是信号发生器波形类型（0..13），不是垂直档位——这是纠正过的历史
误判，实机证据见 [ANALYSIS.md](ANALYSIS.md)。

`0x0D` 不导航页面，逐步复刻原厂按键链路：写字段 → 调原厂配置函数（垂直档位
必须调 `0x08008754(idx)` 切前端衰减/增益，只写字段波形不会变）→ 推 UI 事件 3、1。
角色：`1` 时基（`+0x0D`）、`2` 垂直（`+0x01`，上限 8）、`3` 探头（`+0x03`）。
`0x0F` 用当前字段值重跑一遍，值没变也重算，用于排查。`0x0E` 只放行
`0x20000000..0x200002FF` 与 `0x20004F80..0x20004FFF`。

### 8.7 内存读取（`0x08`）

负载：4 字节小端地址 + 1 字节长度（0 = 256）。放行范围：

| 区域 | 范围 | 约束 |
|---|---|---|
| 片内 SRAM | `0x20000000..0x2000BFFF` | `len ≤ 0x2000C000 − addr` |
| USD | `0x1FFFC000..0x1FFFC1FF` | `len ≤ 0x1FFFC200 − addr` |
| CRM 复位标志 | `0x40023800..0x400238FF` | 只读；`0x40023874` 为标志寄存器 |

单次 ≤512 字节，越界/超长静默丢弃。上界 `0x2000C000` 是三点写入实测结论（写
`0x2000C000` 即复位），协议按实测收紧而不是按标称 384KB 放行。CRM 复位标志位：
bit26 NRST / bit27 POR / bit28 SW / bit29 WDT / bit30 WWDT / bit31 LOWPOWER。

### 8.8 数据源（`0x10`）与画面块

`0x10` 选源后 `0x01`/`0x02` 的语义：

| 源 | `0x01` | `0x02` |
|---|---|---|
| 0 原始采样 | 立即一帧 4096 点 | 连续发送 |
| 1 屏幕波形 | 立即一帧 301 点 | 连续发送 |
| 2 屏幕画面 | 武装一次扫屏（预算 64 块）+ 请求当前页重绘 | 武装至 `0x00` |

换源会先停掉进行中的连续发送与画面流。画面块负载（标志 `0x20`）：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 2 | x |
| 2 | 2 | y（块首行） |
| 4 | 2 | w |
| 6 | 2 | h |
| 8 | w·h·2 | RGB565，行优先，小端 |

没有整屏缓冲（可用 SRAM 48KB < 一帧 153600 字节），设备在每次推屏时把该区域
按行切块直发（`h` 取满足 `8 + w·h·2 ≤ 4096` 的最大值），主机按坐标贴图，后到
覆盖先到。带宽约 64KB/s（单 64B 包在途，约 1ms/包）：整屏 153600 字节理论下限
约 2.4 秒，实测主界面约 5 秒、菜单页 1 秒内。武装时固件按页面号查原厂表投递
绘制单元，所以一次 `0x01` 即当前页完整画面；页面 1/5/6/7 原厂不重建，收 0 块
属正常。

发送期间命令层只受理 `0x00`：画面流占用端点时其他命令一律丢弃，否则整帧卡死。
每包约 30ms 超时，主机不读或掉线时自动放弃并解除武装。

## 9. 主机解析约定

1. 字节流中搜索 `A5 5A` 定帧头；
2. 长度为 0 或 >16384 → 丢 1 字节重新搜索；
3. 数据不足时等待，不提前判错帧；
4. 校验失败且无 CHK_ADV → 丢帧重新同步；
5. 统计丢弃字节数与校验失败次数。

参考实现：`tools/host/phosphor_proto.py` 的 `FrameParser`（`feed()` 返回完整帧
列表，`reset()` 清缓冲）。

## 10. 兼容与扩展

- 新命令从 `0x11` 起分配；`0x09`–`0x0C` 为回收段，`0x0D`–`0x10` 已占用；
- 设备对未知命令静默，固件与主机可独立升级；主机必须为无响应命令设超时；
- `0x10` 为 R35 起新增：旧固件静默忽略，主机可先发 `0x10 0x00` 再发 `0x01`
  兼容旧固件；`0x03` 在所有版本可用；
- 标志位 6–7 与帧格式保留字节留作扩展；改动帧格式必须递增协议主版本并在本节
  登记对应关系。
