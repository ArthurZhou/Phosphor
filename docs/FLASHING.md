# 刷写与恢复

固件通过设备自带的 IAP（In-Application Programming，原厂引导程序提供的免拆机刷写
通道）写入。引导程序位于 Flash 起点 `0x08000000..0x08005FFF`，与 APP 镜像相互独立，
本项目的补丁从不改写这段区域——因此即使 APP 刷坏了，IAP 入口依然可用，设备总有
救回的办法。

## 1. 前置条件

| 项目 | 要求 |
|---|---|
| 待刷产物 | `firmware/PHOS_V1.6R36.bin`（或你构建的对应修订号），已通过静态自检 |
| 恢复产物 | `firmware/vendor/APP_DSO153_V1.6_20240427.bin`（自行备份，仓库不分发） |
| 数据线 | 带 D+/D− 芯线的 USB Type-C 线 |
| 主机 | Windows 10 及以上，或支持 USB 大容量存储的 Linux（Linux 路径 TODO(需验证)） |
| 电量 | 50% 以上 |

自检未通过的产物不允许刷写：构建脚本在自检失败时返回非零退出码并拒绝出片。

## 2. 进入 IAP 模式

顺序不可调换：

1. 长按电源键**完全关机**（屏幕彻底熄灭，不是待机）；
2. 按住 `AUTO` 不放；
3. 保持 `AUTO`，再按住电源键不放；
4. 两键都不松，把 Type-C 线插进主机；
5. 继续按住约 3 秒。

成功标志：主机出现一个名为 `AT32 Msc iap` 的可移动磁盘，设备屏幕不进示波器界面。

没出现磁盘时，依次检查：线是不是纯充电线、有没有插在 Hub 上（改插主机本体）、
设备是不是只待机没关机、按键是否确实按住了。

## 3. 确认磁盘

```bash
python tools/host/check_iap.py
```

脚本只读，列出可移动磁盘的盘符、卷标与根目录，不写入任何字节。确认目标卷标是
`AT32 Msc iap` 再继续。

关于这个磁盘的容量显示：它报告约 8MB，但这是引导程序构造的虚拟 FAT 文件系统
（2048 字节/扇区 × 4095 扇区），不代表芯片真实的 Flash 映射。不要试图从它里面
读出原厂固件——读不到。

## 4. 写入

把固件文件复制到 `AT32 Msc iap` 磁盘的根目录，等复制完成。设备随后自动重启，
看到重启迹象（屏幕亮起、示波器界面出现）就可以松开按键。

写入约需 10–30 秒。期间如果磁盘反复消失又出现，说明按键松了或线缆接触不良：
重新走一遍第 2 节再试。

## 5. 验证

按顺序做四件事：

```bash
# 1. USB 枚举：应出现 0x2E3C:0x5740 的串行设备
python tools/host/usb_devices.py

# 2. 串口可见并标记为目标设备
python tools/host/phosphor_cli.py --list

# 3. 数据通路：应输出一帧 4096 点样本与统计值
python tools/host/phosphor_cli.py -p COM13 -n 1

# 4. 诊断：应输出栈峰值与复位原因
python tools/host/phosphor_cli.py -p COM13 --diag
```

再看设备"设置 → 关于"的版本号，应显示本次构建的版本串（R36 → `V1.6SI`）。
文件名修订号与显示串不是一回事，规则见 [RELEASING.md](RELEASING.md)。

## 6. 恢复原厂固件

1. 按第 2 节进入 IAP 模式；
2. 把备份的原厂镜像 `APP_DSO153_V1.6_20240427.bin` 复制到该磁盘；
3. 等待自动重启，"关于"页恢复显示 `V1.6` 即成功。

恢复后 USB 串口消失是预期行为——原厂固件没有这条数据通道。

## 7. 故障处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 磁盘没出现 | 纯充电线 | 换数据线 |
| 磁盘没出现 | 插在 Hub 上 | 改插主机本体端口 |
| 磁盘没出现 | 设备只是待机 | 长按电源完全关机再来 |
| 磁盘反复消失 | 按键松开 / 接触不良 | 保持按键，换线重试 |
| 写了但版本没变 | 复制错了磁盘 | 用 `check_iap.py` 核对卷标 |
| 写完无显示 | 产物不完整或写入被中断 | 重进 IAP 刷原厂镜像 |
| 开机即复位 | 固件故障 | 用 `phosphor_diag.py` 读复位原因与故障现场定位；先刷回原厂保设备可用 |

## 8. 安全约束

- 只向 `AT32 Msc iap` 卷写固件，该卷不放其他文件；
- 写入过程不断电、不拔线、不松键；
- 补丁不碰原厂栈边界：补丁变量区放在初始 SP（`0x2000B580`）之上的
  `0x2000B800..0x2000BFFF`，原厂 4096 字节栈（`0x2000A580..0x2000B580`）保持
  完整；
- 刷写风险由操作者承担；本仓库代码采用 MIT 许可证，原厂镜像版权属 FNIRSI。

## 9. 历史产物

更早修订号的构建产物保存在 `firmware/legacy/`，仅供回退对照，没有维护义务；
日常使用请以最新修订为准。
